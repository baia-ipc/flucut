How it works

One read, one amplicon

  • the primer is searched only near the read end, aligned with errors, on both strands, degenerate bases and all
  • the sequence after the primer (a probe) is located in the segment: at the terminus it is a real amplicon, deeper inside it is internally primed
  • an internal or unsure end loses its whole primer (cut when unsure), so the artefact never reaches the consensus
  • Nanopore adapters (native, rapid, ligation) removed at broken ends; one IRMA-ready FASTQ per sample
Built for the protocol

No primer files, no tuning

Uni12 / Uni13 mbt tailed uni Nanopore Illumina FASTQ / BAM MinKNOW dirs
  • the schemes and primers are built in — no -g/-a/-e to guess
  • the error rate is measured on the first reads (-e auto); a Nanopore and an Illumina profile (-p)
  • with -r, the conserved 12/13-base termini are kept at the ends confidently terminal — complete segment ends in one pass

What the others miss

See the internal priming — don't just trim it

Every primer-aware trimmer removes the Uni12 footprint. Only flucut tells you it was there: it reconstructs the coverage of each segment from its own read classification, so internal priming shows as a step up above the full-length baseline — here on the HA, in a real H5N1 Nanopore run.

Coverage by read origin (SRA SRR36760543, complete H5N1 segment references). Green: full-length amplicons, a flat baseline. Amber + blue: internally primed reads, by strand, beginning at the red site line. HA steps up sharply at the artefact; PB1 shows a smaller internal site.

Real time

Live, while you sequence

With --live, flucut follows a MinKNOW run: each new file is trimmed as it is written, and the report and JSON summary are updated and reloaded in the browser — the internal priming of the run building up live, on the sequencing laptop. Resume, interruption and end-of-run are handled, and the output matches a normal run on the final files.
